# Skill: weather-station-architecture

## Назначение
Главный архитектурный контракт проекта метеостанции.

## Слои
```text
Hardware
  ├─ BMP280 (I²C)
  └─ DHT11 (GPIO)
       ↓
Sensor layer
       ↓
Weather data model
       ├─ validation/status
       ├─ timestamps
       └─ threshold classification
       ├───────────────┐
       ↓               ↓
HTTP/SSE/Web UI       LVGL UI
       ↓               ↓
Browser             ILI9341/другой дисплей
```

## Данные
Единая модель должна содержать:
- temperature °C;
- humidity %;
- pressure hPa;
- timestamps;
- valid/stale/error state.

## Presentation modes
Единый набор данных должен подаваться во все четыре визуальных режима: numeric, horizontal, bars, gauges.

## Устройство сети
ESP32 — локальный сервер метеостанции. Рабочая сеть: SSID `Beeline_2G_F121F9`. ESP32 использует статический IPv4 `192.168.1.111`, маску `255.255.255.0`, шлюз `192.168.1.1`, DNS1 `192.168.1.1`, DNS2 `1.1.1.1`. Браузер в той же локальной сети открывает `http://192.168.1.111/`.

## Сетевой контракт
- `192.168.1.111` — зарезервированный статический адрес ESP32.
- Не использовать DHCP для рабочего режима.
- Не хардкодить пароль Wi-Fi в source/skills; секрет хранится в `include/secrets.h`.
- Не использовать другие сетевые параметры: сетевой контракт проекта фиксирован явно выше.

## Архитектурные ограничения
- Никаких зависимостей UI от конкретного сенсора.
- Никаких зависимостей веб-клиента от LVGL.
- Никаких блокирующих сетевых запросов в sensor loop.
- Все пороги и интервалы — конфигурация.
- Сборка должна воспроизводиться через PlatformIO.
