# Skill: esp32-debugging

## Назначение
Стандартизирует диагностику ESP32 и не допускает, чтобы агент исправлял проблему вслепую.

## Порядок диагностики
1. Скомпилировать проект.
2. Загрузить прошивку.
3. Открыть Serial Monitor.
4. Проверить reset reason.
5. Проверить I²C scan.
6. Проверить BMP280.
7. Проверить DHT11.
8. Проверить Wi‑Fi/IP.
9. Проверить HTTP API.
10. Проверить LVGL/display.
11. Только после этого оптимизировать.

## Логи
Использовать единый формат:
```text
[BOOT]
[SENSOR][BMP280]
[SENSOR][DHT11]
[WIFI]
[HTTP]
[LVGL]
[ERROR]
```

## Правила
- Каждая аппаратная ошибка должна иметь контекст.
- Не устранять reset loop увеличением delay без понимания причины.
- Не маскировать `NaN`, timeout или checksum error заменой на ноль.
- Для памяти логировать heap при подозрении на fragmentation.
- После каждого исправления повторять минимальный regression test.
